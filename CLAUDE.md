# Claude workspace

Это единственный репозиторий для всей работы: проекты, рабочие файлы, скиллы и MCP-конфиги. Все данные берём отсюда.

## Структура
- `projects/<имя>/` — каждый проект в своей папке (сайты деплоятся на Vercel).
- `.claude/skills/` — скиллы: `ui-ux-pro-max`, `shadcn`, `frontend-design`, `impeccable`, `design-taste-frontend` (Taste), `motion-react`, SEO (`seo*`, `geo*`, `schema`, `programmatic-seo`), блог (`blog*`), текст (`humanizer`, `plain-writing`, `concise-writing`), `token-efficiency`, `minimal-execution`, `smart-file-reading`, `selective-testing`, видео (`watch` — ролики по ссылке, `video-understand` — локальные файлы: кадры + речь с таймкодами).
- `.mcp.json` — MCP-серверы: `shadcn`, `vercel`.

## Правила
- Новые проекты, скиллы и MCP создаём только в этом репозитории и коммитим сюда.
- Сайты размещаем на Vercel (Vercel MCP / Vercel Git-интеграция на этот репозиторий; Root Directory = `projects/<имя>`).
- Для UI: сначала скилл `ui-ux-pro-max`, компоненты — shadcn (через shadcn MCP).
- Astryx (Meta design system): официального MCP нет, работает через CLI `@astryxdesign/cli` (`astryx init` пишет гайд в AGENTS.md/CLAUDE.md проекта).

## Работа с картинками (Codex)
- Картинки для сайтов генерирует Codex (ChatGPT), не Claude. Инструкции для него в `AGENTS.md`.
- Для каждого сайта Claude кладёт заглушки в `projects/<имя>/public/images/` и пишет `projects/<имя>/IMAGES.md` по шаблону `templates/IMAGES.md`: имя файла, размер, пропорции, готовый промпт.
- Codex пушит картинки в ветку `codex/images-<имя>`. Claude мерджит её в рабочую ветку, проверяет сайт и деплоит на Vercel.
- Пока Codex не прислал картинки, сайт должен нормально выглядеть на заглушках.

## Обязательное применение скиллов
Все скиллы из `.claude/skills/` используем везде, где они подходят, без напоминаний от пользователя. Перед задачей определи подходящие скиллы и вызови их через Skill.

| Когда | Скиллы |
|-------|--------|
| Любой сайт, страница, компонент, редизайн | `ui-ux-pro-max`, `frontend-design`, `design-taste-frontend`, `impeccable`; компоненты через `shadcn` + shadcn MCP |
| Анимации и переходы | `motion-react` |
| Любой публичный сайт (SEO-основа) | `seo` (+ `seo-page`, `seo-technical`, `seo-sitemap`), `schema` / `seo-schema` для JSON-LD |
| Видимость в AI-поиске (ChatGPT, Perplexity, AI Overviews) | `geo`, `seo-geo`, `geo-llmstxt`, `geo-crawlers` |
| Много однотипных страниц (города, каталоги, сравнения) | `programmatic-seo` / `seo-programmatic` |
| Статьи и блог | `blog` и подскиллы `blog-*` (`blog-write`, `blog-outline`, `blog-seo-check`, `blog-schema` и др.) |
| Любой текст сайта и сообщения (тексты страниц, тексты для пользователя, описания) | `plain-writing` и `concise-writing`; готовый текст всегда прогоняем через `humanizer` |

Примечания:
- Хук-проверка `concise-writing` (`scripts/concise_check.py`) не подключена, скилл используется как руководство по стилю. Тексты на русском пишем простым языком, короткими предложениями.
- Аудиторные скиллы (`seo-audit`, `geo-audit`, `blog-audit`) запускаем перед публикацией сайта на Vercel.

## Стиль ответов пользователю (всегда)
- Пиши по-русски, кратко и понятно: пользователь читает с телефона на ходу.
- Сначала результат в 1–2 строки, затем короткие пункты. Без длинных объяснений, таблиц и ссылок без нужды.
- Не больше одного вопроса в конце, только если без ответа нельзя продолжить.
- Скиллы вызываем на каждой подходящей задаче, не только по просьбе. Хук в `.claude/settings.json` напоминает об этом при каждом сообщении.
- `token-efficiency`, `minimal-execution`, `smart-file-reading`, `selective-testing` применяем всегда: экономим токены, делаем минимум действий, читаем только нужные участки файлов, тестируем только изменённое.
- Видео: если пользователь присылает ролик (запись экрана с правками) или ссылку на видео, разбираем его скиллами `watch` / `video-understand`. Нужны ffmpeg и Whisper.

## База знаний: Threads → Telegram → клиенты
Папка `threads-knowledge-base/` (автор материалов — Дмитрий Петрушин). Перед задачами про Threads, контент, воронку и продажи читаем её.
Конспект:
- Воронка: пост в Threads (польза + узнаваемый голос) → закреп/материал в Telegram → прогрев → заявка → диагностика → оплата.
- Темы берём из вопросов и комментариев клиентов в нише. Сначала покупатель и его ситуация, потом тема.
- Повторяемый формат важнее разовой темы: серия постов с одним заходом, сравнение по результатам.
- Заголовок: знакомая ситуация + конкретика. Тест: закрой имя — мог ли написать любой коллега?
- Прогрев: личность, экспертность, подход к решению, оффер. Цикл решения длинный (у автора ~41 день).
- Лид-магнит: разбор реальной задачи с пользой «на выходе» и одним чётким следующим шагом.
- Метрики по шагам: просмотры → переходы в профиль → переходы в материал → диалоги → диагностики → оплаты. Считать конверсию между соседними шагами.
- Практика: 30-дневный тест (`practice.md`) с журналом метрик. Цифры автора — примеры, не обещания.
- Не расшифровано: часть аудио/видео (список в `videos.md`, `sources.md`). Если нужен непрослушанный материал — говорим об этом прямо.

### xxxdimacion | трафик (`threads-knowledge-base/xxxdimacion-traffic.md`)
Автор платит за принятого подписчика/заявку (~120 ₽, у автора), ведёт трафик из Threads, Instagram и коротких видео в Telegram.
- Конверсия просмотр→переход в канал по данным автора: ~0,35–1,7%. Свои цифры берём только из своих тестов.
- Если просмотры не дают переходов: после перехода нечего получить или ролик слишком для всех. Ведём на конкретный материал.
- Три формата Threads: результат, материал за пределами поста, личное наблюдение с вопросом.
- Тест формата: фиксируем дату, формат, просмотры, переходы, диалоги; сравниваем медианы серии.
- Юнит-экономика: окупаемость = затраты / ставка за зачтённую заявку; учитываем долю отклонений и срок выплаты.
- Пересчёт кейсов автора: часть сумм не сходится (пост 148: 506×120 = 60 720, а не 65 тыс.). Цифры автора проверяем арифметикой.
- Инструкции по обходу модерации/спама в конспект не входят.
